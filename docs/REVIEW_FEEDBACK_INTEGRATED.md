# Review feedback integrated in v7

- Random Forest is explicitly qualified as sequence-based, not time-aware.
- Minimum forecast activation increased from 8 to 30 chronological sequence samples.
- Separate recording-session IDs are generated by the Ubuntu sensor.
- Temporal train / validation / test partitions are separated by recording/session time.
- No hard-coded behavioural fallback forecast is shown; the UI uses **INSUFFICIENT EVIDENCE**.
- T5/T6/T7 use separate horizon classifiers and confidence gating.
- Online forecast evaluation reports next-stage accuracy, macro F1, precision, recall, false-positive rate and a confusion matrix.
- Stage-transition forecasts are verified separately from same-state forecasts.
- Correct transition lead time is measured from forecast issue to later observed behaviour.
- Hybrid risk formula is implemented and documented as 0.50 ML + 0.30 anomaly + 0.20 signature.
- Benchmark attack category remains separate from ChronoFlux behaviour stage and MITRE-style interpretation.
- Evidence branding now accurately describes the implementation as a tamper-evident SHA-256 hash chain.
